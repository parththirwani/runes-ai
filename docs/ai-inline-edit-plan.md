# AI inline edit for the Runes AI editor

Status: implementation handoff. References are the public [Arc UI AI inline edit preview](https://uiarc.dev/components/blocks/ai-inline-edit) and [Arc UI Ghost text preview](https://uiarc.dev/components/ghost-text), inspected on 1 November 2026. Their source and install commands require Pro access. Recreate the public interaction and visual details in Runes AI's existing editor without assuming either private package or source is available.

## Goal

Let an editor select prose, press Ctrl/Cmd+K or tap an Edit action, enter an instruction or choose a quick action, and review the proposed replacement beside the source before applying it. Match the public reference's visible states, placement, keyboard behavior, word diff, per-change review, and ghost text as closely as Monaco and protected source syntax allow. AI must never silently change a file.

The target is Markdown and LaTeX source in Monaco, not Arc's plain-paragraph `contenteditable`. Preserve Markdown syntax, LaTeX commands, the current workspace file model, save/autosave, PDF compilation, and the existing side panel for non-editing AI tasks.

## What the reference does

Arc's public demo and API description show a selection bubble, a Ctrl/Cmd+K prompt anchored below the selection, quick actions plus free instructions, streamed replacement text, an inline word diff, per-change and all-at-once review, undo, and short ghost text accepted with Tab. With no selection, Ctrl/Cmd+K targets the sentence around the caret. Escape closes or cancels the active state. The public usage example expects an `onRequestEdit` callback that returns a string or an async stream and an `onSuggest` callback for completion. Arc says its demo suggestions are scripted. These observations describe behavior; they do not give us the Pro implementation.

The separate [Ghost text component](https://uiarc.dev/components/ghost-text) is the detailed autocomplete reference. Its public demo is a pull-request description field. The documented behavior is: wait 450 ms after typing; show a muted continuation at the caret as chunks arrive; Tab accepts all; Cmd/Ctrl+Right accepts one word and keeps the remainder; Escape dismisses; typing characters that match the ghost consumes them locally; moving the caret away clears it. The corner chip names the active model and changes through Thinking, Tab to accept, Accepted, and No suggestion with Retry. On touch it becomes a tap-to-accept control. Its demo uses scripted suggestions and its implementation is a textarea/input, so Runes must adapt the behavior to Monaco rather than copy that DOM structure.

## User flow and decisions

1. When a writable prose selection is eligible, show a small Edit button near it. Ctrl/Cmd+K opens the same prompt. Do not capture that shortcut outside the editor. A touch selection gets the same Edit button. Read-only users see neither action.
2. If there is no selection, Ctrl/Cmd+K selects the sentence containing the caret only when a deterministic Markdown or LaTeX prose scanner can identify one eligible range. If it cannot, show a short reason and leave the source unchanged. Never send a whole file or an arbitrary line as fallback. Limit one edit to one prose block and the existing selection size cap. Reject a cross-block or protected selection with an explanation.
3. The prompt offers `Shorter`, `Clearer`, `Formal`, and `Fix grammar`, plus a free instruction field. A quick action sends a server-defined instruction ID; free text has a length limit and is validated server-side. The user's instruction must not override the rules that preserve syntax and protected tokens.
4. While the response arrives, show a Stop control and a progress status near the selection. Keep original source bytes in Monaco. Display streamed words as a preview decoration or overlay, with removed and added words marked by strike-through/underline and labels. If the chosen Monaco rendering approach cannot maintain caret and selection stability, show the diff in an anchored review card instead. Do not insert provisional AI text into the model.
5. On completion, offer per-change Accept/Reject, Accept all, and Reject all, with clear keyboard and touch controls. Tab moves among changes; Enter accepts a focused change; Backspace rejects it; Ctrl/Cmd+Enter accepts the rest. Keep the source unchanged until the review decision is committed. The final approved replacement applies as one Monaco undo step only after rechecking document ID, workspace path/model URI, model version, original bytes, and proposal state. Reject all, navigation, or a stale result leaves source untouched. An accepted edit uses the normal dirty/save path and marks the PDF stale.
6. Keep one proposal active per editor. Starting a new edit, changing files, toggling read-only state, or unmounting cancels the request and clears its decorations. Undo/redo remains Monaco's normal behavior after Accept. The old toolbar and side-panel entry points may open the new prompt with the current selection; remove duplicate review UI only after tests cover both entry paths.

### Per-change review

Build a pure hunk model from the original selection and validated replacement. Each word-level change must have a stable ID and an accept/reject decision. Accepted hunks contribute suggested text; rejected hunks retain original text. Protected Markdown and LaTeX spans remain byte-for-byte intact. After the last decision or Accept all, assemble one final replacement, rerun format validation, recheck the exact source range, and commit one undoable Monaco edit. If the assembled text would violate syntax protection, block Apply and explain why. Do not present per-change controls that merely accept the entire proposal.

### Ghost text autocomplete

1. Keep Monaco's source model as the editable text and render the suggestion with its inline completion/decorations, not an overlaid textarea. Start after roughly the reference's 450 ms pause (the current provider uses 400 ms). Only request in eligible Markdown or LaTeX prose, with enough preceding text and the caret at a safe continuation point. Return no suggestion for code, math, commands, links, protected Markdown, selection, review, or read-only state. Keep the existing format-specific validation and the server's insertion-only output rule.
2. Extend `/api/ai/complete` to stream bounded insertion deltas when the provider supports it; keep a single-response fallback. Show complete chunks without shifting the caret. Abort and ignore late chunks when the user types, moves the caret, blurs or switches editor/file/document, disables AI, or accepts/dismisses the suggestion. Never insert streamed text before acceptance. A request that fails shows a retryable error state without blocking typing.
3. Tab accepts the full visible suggestion. Cmd/Ctrl+Right accepts the next word and leaves the suffix visible; support Alt/Option+Right where it does not conflict with Monaco or platform navigation. With no suggestion, these keys keep their normal editor behavior. Typing a matching prefix trims the ghost locally; a mismatch clears it and restarts the debounce. Escape dismisses without changing source. Verify whole and word acceptance remain undoable and mark only the active file dirty.
4. Add a compact status chip tied to the real configured provider/model: idle model name, Thinking, Tab to accept, Accepted, and No suggestion/Retry. Do not hard-code the Arc demo's Claude label if Runes uses another model. The chip accepts by tap on touch devices and must not steal editor focus. Announce the ready suggestion and accepted/dismissed/error states through a polite status region; keep ghost text out of screen-reader document content. Use text labels as well as color. Match the reference's calm fade and fixed caret placement, with reduced motion removing animation.
5. Compare Runes' ghost text, chip states, word acceptance, responsive layout, and keyboard behavior against the Ghost text screenshots. Monaco's native inline rendering can differ from Arc's mirrored textarea; document any difference with side-by-side images rather than introducing a second source editor.

## Implementation sequence

1. **Selection and state.** Add an editor-scoped state machine (`idle`, `prompt`, `requesting`, `review`, `error`) and pure selection helpers. Capture document ID, active workspace path, Monaco model URI/version, offsets, original bytes, and format. Position the bubble/card from Monaco selection coordinates and clamp it inside the editor on resize or scroll. Restore focus and selection when dismissing the prompt. Add a non-hover trigger for touch and keyboard users.
2. **Request contract.** Extend the paraphrase route or add `POST /api/ai/inline-edit` with a typed discriminated request for quick action ID or bounded free instruction. The server derives format from the writable document. Reuse the existing Markdown and LaTeX selection analyzers and response validators. Return only replacement text, a no-op, or a safe error. Keep quotas, one active AI slot per user, 15-second provider timeout, 10,000-character selection cap, and response-size checks. Never log source, instruction, or raw provider output.
3. **Streaming.** Add streaming replacement deltas with an explicit protocol, terminal success/error event, maximum cumulative bytes, and abort propagation to the provider. Validate the assembled replacement before enabling review decisions. While streaming, reveal complete words in the diff. Stop keeps the received words as a reviewable partial suggestion only if the server can validate that partial replacement against protected syntax; otherwise Stop discards it and explains why. A non-streaming provider may return one final replacement through the same UI state machine.
4. **Anchored review.** Reuse `computeDiff` for word-level tokens, add the pure hunk builder, and show the diff and per-change controls at the selection. Use Monaco decorations or view zones only if they stay aligned through scrolling and wrapping. Do not render a second editable document. Announce request, completion, failure, and stale states. Use strike-through and underline plus text labels, not color alone. Respect reduced motion and narrow viewports. Compare each state with the captured Arc screenshots and record differences.
5. **Completion and existing UI.** Implement the Ghost text section in the existing Monaco completion provider and `/api/ai/complete` route. Suppress ghost text during prompt/request/review. Resolve Tab, word-accept, and Escape precedence with Monaco's command actions and existing app shortcuts. Route toolbar and side-panel paraphrase controls through the new controller, then remove only redundant controls and their dead state.
6. **Verification and release.** Add focused pure tests, route tests, and a browser interaction test. Run all repository quality gates. Open a `feat/` PR to `dev`, get review, and verify the feature in `dev` before a later release PR to `main`.

## Acceptance checks

- Markdown and LaTeX prose selections can open the prompt by keyboard, pointer, and touch. Read-only users cannot request edits. Ctrl/Cmd+K outside Monaco keeps the app's normal behavior.
- Quick actions and a free instruction produce a valid replacement. Empty/oversized instructions, protected or cross-block selections, missing provider, rate limit, concurrent request, timeout, and malformed AI output show an error without changing source.
- Request and review states remain anchored as the editor scrolls or resizes. Escape, Stop, Reject, file switch, document switch, typing during a request, and unmount cancel or invalidate the suggestion. Late responses never appear in another file.
- Accept applies exactly one undoable edit to the active file. Reject changes zero bytes. A stale proposal cannot apply after any model change, even if the same original text appears elsewhere. Save/autosave and PDF staleness still work.
- Markdown links, image URLs, inline code, math, emphasis, front matter, and structure remain protected. LaTeX commands, citations, references, math, and environment delimiters remain protected. Provider instructions cannot bypass these checks.
- Ghost text appears only in eligible prose. Tab accepts all, Cmd/Ctrl+Right accepts one word while retaining the remainder, matching typing consumes the ghost, and Escape dismisses it. Late chunks never insert into a changed model. The model/status chip, touch acceptance, Retry, and screen-reader announcements work without stealing editor focus or conflicting with prompt/review shortcuts.
- Per-change Accept/Reject and Accept all produce the expected final text. Rejected hunks retain original bytes; protected syntax is still valid; the final application is one undo step. Stop either exposes a validated partial review or discards an invalid partial result.
- Reference screenshots from both Arc pages and same-size Runes screenshots show each public demo state, with visual differences documented. The implementation includes reduced-motion and mobile checks.
- Tests cover the state machine, selection bounds, stale model/path checks, API authorization and validation, aborted requests, hunk decisions, diff rendering, and keyboard/touch interactions. Existing AI, editor, save, and access tests remain green.
